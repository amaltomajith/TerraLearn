### 2.1 PR1 — global floating assistant + memory + fast answers (`810ab03`)

**UI**

- New `src/components/assistant/` (`GlobalAssistant`, `AssistantPanel`,
  `AssistantMessageBubble`) and `src/lib/assistant/` (`AssistantProvider`, `queries`,
  `api`, `useAssistantPageContext`, `renderMarkdown` + `MarkdownInner`, `types`).
- Mounted **once** in `src/auth/RootGate.tsx` above `<Routes>`, inside `IdentityProvider`
  / `RequireOnboarding` — so it appears on the simulator **and every `/saath/*` page**,
  and the conversation survives route changes.
- Desktop = `position: fixed` anchored panel (`bottom-20 right-4`, ~380×560) that **never
  reserves document flow** — this is the fix for "pushes the page down / cramped". Mobile =
  bottom sheet with a backdrop. FAB `fixed bottom-4 right-4 z-[901]` with a framer-motion
  hover label and a "thinking" pulse.
- Deleted `src/components/AskTerraLearn.tsx` + `src/components/DockedAssistant.tsx` (only
  `home.tsx` and each other referenced them). `home.tsx` now publishes its existing
  `position` / `cropContext` / `assistantContext` memos to the assistant via
  `useAssistantPageContext(...)`.
- Assistant answers render markdown — `react-markdown` + `remark-gfm`, **lazy-loaded** into
  its own ~48 KB-gzip chunk (`MarkdownInner-*.js`); entry bundles unchanged.

**Memory**

- `AssistantProvider` loads the farmer's latest thread on mount, defers thread creation
  until the first send, persists every turn, and subscribes to `assistant_messages` for
  multi-tab sync. Survives navigation and full page reload.
- The backend stays **stateless** — the client sends the last ~10 turns (`history`) plus
  light identity (`farmerName` / `village` / `farmerLanguage` / `enterprises`) each call.
- Double-submit guarded with a synchronous `sendingRef`.

**Speed + tone (`backend/app/agent.py`, `main.py`)**

- New `build_system_prompt(language, name, village, enterprises)`: reply **only** in the
  mapped language (`kn`→Kannada default, `hi`, `en`, `ta`, `te`, …); lead with the answer
  in sentence one; ≤ ~60 words unless asked to explain; class-6 reading level; mention only
  the one or two numbers that matter; **never invent a number**; only call the slow
  `get_climate_aqi_data` tool when the question needs multi-year history / live readings not
  already in the prompt.
- Module-level caches: one `httpx.Client`, and `create_react_agent` memoised by
  `(api_key, base_url, model)` — no per-request graph rebuild.
- `run_agent(user_input, history, system_prompt)` builds `[SystemMessage, *history,
  HumanMessage]`. The whole retry / fallback / `tool_use_failed` / `model_not_found` state
  machine is preserved. `_last_answer` now only returns real **AI** messages (it was
  echoing the prompt when the agent produced nothing).
- `/api/ask` is now non-blocking (`asyncio.to_thread`, like `/api/risk-brief`); `lat`/`lng`
  optional.
- `smoke_test.py` check (b) updated for concise answers — verifies a grounded fact
  (figure or named source) instead of answer length.
- `backend/.env.example` `OPENAI_MODEL` synced to `openai/gpt-oss-120b`.

**Warm p50 expectation:** ~8–20 s → ~2–4 s.

### 2.3 PR3 — draft-and-confirm messaging (`7f4b627`)

**Protocol.** When the farmer asks to message someone, the model appends after its prose:

````
```terralearn-action
{"type":"send_message","recipientName":"<name from the Saath block>","body":"<message, in the farmer's language>"}
```
````

The model proposes a **name only** — never an id.

**Backend (`agent.py` `extract_action`, `main.py`).** Regex-extract the block, `json.loads`,
validate shape, **strip it from the answer**, return `AskResponse.action`. Any parse/shape
problem fails soft to prose-only. Not a LangChain tool (Groq's tool-calling is flaky and a
proposal has no reason to round-trip the model).

**Frontend.**

- `AssistantProvider.resolveRecipient(name, snapshot)` — matches the proposed name against
  the Saath snapshot (exact → prefix → substring), returning `{id, name, village?,
  distanceKm?, threadId?}`.
- `AssistantActionCard` renders in the assistant bubble: recipient + village/distance,
  editable message body, **Send** / **Dismiss**. A name **not** in the snapshot shows an
  amber "not found — check the name" warning and **disables Send**.
- `confirmSend(messageId, editedBody)` → `threadIdFor(me, id)` (if no existing thread) →
  the **existing** `sendMessage()` as the signed-in user → marks the message
  `meta.actionSentAt` → drops a "Sent to X" system line. The card collapses to
  "✓ Sent to X · View in Messages" linking `/saath/messages/<thread>`. Persists across
  reload (card stays collapsed, no re-offer).

**Safety.** Nothing sends without the tap. RLS enforces `sender_id = current_farmer_id()`.
The backend holds **no Supabase credentials**, so the model has no send path at all — the
confirm step is an architectural guarantee, not just prompt discipline.

**Verified live:**
- "Ask Lakshmamma if she has spare paddy straw" → draft card (recipient "Lakshmamma,
  Kalenahalli · 7.7 km") → edit → Send → `messages` row with `sender_id` = you,
  `recipient_id` = Lakshmamma, `thread_id` = `thread_for(pair)` ✓
- "Send a message to Zephaniah Okonkwo …" (not in network) → Send disabled, **nothing
  inserted** ✓
- Reload → card stays collapsed at "Sent to …" ✓
